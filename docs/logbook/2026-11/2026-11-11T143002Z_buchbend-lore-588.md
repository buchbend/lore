**2026-11-11** · Christof Buchbender · buchbend/lore#588

**Why:** The repo shipped two plugins, `lore` and `lore-workflow`, as one release unit with two versions. A person bumped the second version by hand. A missed bump left old skills in an installed cache. Two skills also had the short name `handover`. [PRD 0021](https://github.com/buchbend/lore/blob/main/docs/prd/0021-one-plugin.md) (one plugin) holds the full problem.

**What we did:** The 11 workflow skills now ship in the `lore` plugin, each named `lore:<name>`. The two handover skills are one skill with two parts. We made a clean break and ship no alias skills. An alias doubles the skill listing ([ADR 0021](https://github.com/buchbend/lore/blob/main/docs/adr/0021-lore-ships-as-one-plugin.md), Lore ships as one plugin). `lore setup` and `install.sh upgrade` uninstall the old plugin, but only after the `lore` plugin is current. Epic [#588](https://github.com/buchbend/lore/issues/588) (merge lore-workflow into the lore plugin) tracks the work.

**Consequences:**
- Users type `/lore:build`, `/lore:orient` and so on. Each `/lore-workflow:<name>` command is gone.
- Users with the old plugin run `lore setup` once. `lore doctor` fails until the old plugin is gone.
- Maintainers bump one version with `tools/release.py`.
- The glossary holds a new term, Handover note.
