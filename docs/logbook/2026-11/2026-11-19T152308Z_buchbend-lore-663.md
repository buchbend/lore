**2026-11-19** · Christof Buchbender · buchbend/lore#663

**Why:** Undelivered logbook entries piled up unseen. On one machine, 19 entries waited for a sink. 16 of them sat in the ledgers of linked worktrees, and one sat only in an archived ledger. `lore log flush` and the banner read only the ledger of the current checkout ([#658](https://github.com/buchbend/lore/issues/658) (retry across worktrees), [#659](https://github.com/buchbend/lore/issues/659) (retry from an archived ledger)).

**What we did:** `lore log flush` now reads the ledger of every checkout of the repo, and the archived ledgers beside each one ([PR #663](https://github.com/buchbend/lore/pull/663)). Lines with one key merge into one entry, and a sink counts as delivered when any line says so. We merge by key, not by file order, because the date suffix of an archive does not sort by time. A flush skips a locked ledger and goes on with the others. `archive_ledger` now takes the same lock.

**Consequences:**
- Users: the SessionStart banner and `lore status` count the entries of all checkouts. One `lore log flush` retries them all.
- Nobody outside this repo notices.
