**2026-11-11** · Christof Buchbender · buchbend/lore#583

**Why:** The triage of 2026-11-11 read all 47 open issues against `main`. Eight issues were small, still true and independent of each other. The owner asked for one batch to bring the count of open issues down.

**What we did:** [PR #583](https://github.com/buchbend/lore/pull/583) (fix eight small defects from the triage of 2026-11-11) holds eight fixes:
- The dokuwiki source refuses a secret on an `http://` URL, keeps the token out of a redirect and ends a slow reply at its timeout ([#489](https://github.com/buchbend/lore/issues/489), harden the dokuwiki source). We refuse and do not warn, because a warning still sends the token in plaintext.
- `lore workflow epic-policy` warns when git cannot read `origin` ([#549](https://github.com/buchbend/lore/issues/549), wrong target branch). The issue blamed `origin/HEAD`; the code never read it.
- `create-prd` quotes the title ([#546](https://github.com/buchbend/lore/issues/546)). `file-issue` resolves its draft path once ([#528](https://github.com/buchbend/lore/issues/528)). The test suite clears `LORE_SUPPRESS_CAPTURE` ([#481](https://github.com/buchbend/lore/issues/481)).
- The glossary gains Source list, Undelivered and Candidate edge ([#488](https://github.com/buchbend/lore/issues/488), [#536](https://github.com/buchbend/lore/issues/536)). The logbook how-to shows a working `pm` sink ([#492](https://github.com/buchbend/lore/issues/492)).

**Consequences:**
- Users with a dokuwiki source on an `http://` URL and a secret: the source returns a note and no hits until the URL uses `https://`.
- Agents in a sandbox: `epic-policy` and `spec-branch` say on stderr when `main` is a fallback.
- Other repos: `create-prd` writes front-matter that Vale can parse.

**Not done yet:**
- Not yet checked: that the `lore search` process exits within the timeout against a slow real server.
- Not yet checked: `realpath -m` on macOS, which the `file-issue` skill now calls.
