**2026-11-14** · Christof Buchbender · buchbend/lore#615

**Why:** Lore ran fully only in Claude Code ([#615](https://github.com/buchbend/lore/issues/615), OpenCode as a host). A person on OpenCode lost the banner, the `lore` MCP server, the skills and capture.

**What we did:** `lore setup` writes a generated OpenCode 2.x plugin that only calls the existing `lore hook` commands. The plugin is a generated shim, not a second copy of the Lore logic. The hooks already hold the behaviour, so one version covers both hosts ([ADR 0022](https://github.com/buchbend/lore/blob/main/docs/adr/0022-lore-runs-in-opencode-through-a-generated-plugin.md), Lore runs in OpenCode through a generated plugin). Model tiers become four OpenCode subagents. The spawn gate keeps the Claude Code rule: a spawn needs an agent that pins a model. A person ran the plugin on OpenCode 2.0.32 before the merge.

**Consequences:**
- OpenCode users get the banner, the MCP tools, the `lore:*` commands, capture and token records after `lore setup`.
- Claude Code users notice no change. Agent instructions now live in `AGENTS.md`.
- A pipx install ships the skills, so a person without Claude Code can install.
