**2026-11-11** · Christof Buchbender · buchbend/lore#589

**Why:** The triage of 2026-11-11 left small defects that were still true. One of them could leave a wiki in a half-finished merge with no message. Others made error messages hard to read.

**What we did:** [PR #589](https://github.com/buchbend/lore/pull/589) (fix seven small defects, batch 2) fixes them in one round.

- The wiki push now aborts its merge when an error interrupts it. The next session start names the error.
- `lore log add` and `lore lab add` say what an entry lacks.
- `lore workflow spec-branch` warns when the local and the remote spec branch differ.
- Two fixes for the pending-verdict list left the PR again. Both wikis hold no stale marker and no verdict, so a fix there has no user. The layer needs a keep-or-retire decision first.

**Consequences:**
- A wiki config that still holds `git.auto_commit` gets an "unknown key" warning. The key had no reader.
- Reviewers in `build` pass the full PR URL to `code-review`.
- Nobody outside this repo notices the rest.
