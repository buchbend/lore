**2026-11-11** · Christof Buchbender · buchbend/lore#598

**Why:** Lore still held a note lifecycle from the time of session notes. It had a `superseded_by` relation, a `draft` flag and a rule that called a note stale after 180 days. A hygiene curator wrote these fields into a wiki checkout through no pull request. Neither wiki held one such field. The owner wants a small system before more users arrive.

**What we did:** [PR #598](https://github.com/buchbend/lore/pull/598) (retire the note lifecycle and the hygiene curator) removes the lifecycle, `lore wiki curate` and the `/lore:curator` skill. A note that holds a retired field keeps the field and Lore ignores it. We chose "ignore", not a migration, because no note in the two wikis holds a field. The PR also removes what only the curator fed: the run log, its readers and the banner line "last run had N errors".

**Consequences:**
- Wiki authors: `lore wiki lint` shows no `DRAFT` or superseded badge and warns on no age. `last_reviewed` is optional. A note that is no longer true gets a rewrite in a pull request.
- Wiki admins: a wiki that copied `examples/wiki-curator-on-push.yml` has a CI job that now fails. Delete the job.
- Nothing fills a missing `created` field from git any more.
