**2026-11-14** · Christof Buchbender · buchbend/lore#636

**Why:** The review of [#629](https://github.com/buchbend/lore/issues/629) (five small OpenCode review defects) found four more defects in the OpenCode token trace. [#634](https://github.com/buchbend/lore/issues/634) (four older defects in the OpenCode token trace) collected them. A short prompt could give one subagent the tokens of another.

**What we did:** The trace links a subagent call to its child session by the session ID that OpenCode records on the call. The issue asked for an exact match of the prompt text. A real OpenCode child starts with a one-line preamble before the prompt, so an exact text match never fires. The text match stays as a fallback for a call with no session ID. The cost summary counts 1-hour cache writes. A subprocess test pins the UTF-8 read ([#636](https://github.com/buchbend/lore/pull/636)).

**Consequences:**
- OpenCode users: `lore trace tokens` gives each subagent its own tokens.
- Nobody outside this repo notices anything else.

**Not done yet:**
- Not yet checked: token records for subagents of subagents. The roadmap holds that item.
