**2026-11-14** · Christof Buchbender · buchbend/lore#637

**Why:** `lore off` and `lore on` muted Lore for one session. The mute served the session notes, which [ADR 0007](https://github.com/buchbend/lore/blob/main/docs/adr/0007-session-notes-retired-flags-are-the-crossing.md) (session notes are retired) removed. The reviews of epic [#632](https://github.com/buchbend/lore/issues/632) (Claude Code and OpenCode round trip) found three defects in the OpenCode mute. [#633](https://github.com/buchbend/lore/issues/633) (remove the session mute) asked to remove the mute, not to fix it.

**What we did:** The CLI verbs, the mute file, the hook and MCP checks, the `citations` scope and the OpenCode plugin refusal are gone ([#637](https://github.com/buchbend/lore/pull/637)). Lore adds no cleanup for old mute files. No code reads them, and the operating system clears `$TMPDIR`.

**Consequences:**
- Users: `lore off` and `lore on` no longer exist.
- OpenCode users: run `lore update`. The old plugin keeps its mute check until the update rewrites the plugin.
