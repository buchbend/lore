**2026-11-11** · Christof Buchbender · buchbend/lore#599

**Why:** The curators are gone since [PR #598](https://github.com/buchbend/lore/pull/598) (retire the note lifecycle and the hygiene curator). Their name still sat on live code: the package that holds transcript capture, and the variable that keeps hooks out of child processes. A new reader took the name for a running curator.

**What we did:** [PR #599](https://github.com/buchbend/lore/pull/599) (remove the curator name from capture code and spawn code) moves the two capture modules into `lore_core`. It renames the guard variable to `LORE_CHILD_MODE`. We renamed the guard and did not delete it, because `spawn.py` still starts six kinds of child process from the hooks. The PR also deletes five helpers that only a curator called.

**Consequences:**
- Users: nobody notices in daily use. The first SessionStart after the upgrade starts its child processes once without a cooldown.
- Developers: `lore_curator` no longer imports. Use `lore_core.capture_routing` and `lore_core.ledger_linkage`.
- The event spine has no `curator` source and is at schema version 3. Old spine files still read.
- A session at an unattached vault root now records a `no-scope` event.

**Not done yet:**
- Not yet checked: the old `.lore/curator-<role>.*` lock and stamp files stay on disk. No code removes them.
- Not yet checked: no code enforces the list of spine sources at run time.
