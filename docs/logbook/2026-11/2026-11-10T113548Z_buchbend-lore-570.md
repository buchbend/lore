**2026-11-10** · Christof Buchbender · buchbend/lore#570

**Why:** Epic [#555](https://github.com/buchbend/lore/issues/555) (index-first context and the lab notebook) added `lore workflow spec-branch`. Its reviews found two gaps, filed as [#565](https://github.com/buchbend/lore/issues/565) (spec-branch for cross-repo epics and unpushed branches). The `build` skill did not say in which repo to run the command. A spec branch that existed only as a local branch passed the check, and the merge of `origin/<branch>` then failed.

**What we did:** [#570](https://github.com/buchbend/lore/pull/570) (spec-branch ref) makes the command print a key `ref`: `origin/<name>` when the remote holds the PRD, the local name otherwise. `build` merges the printed ref, not a name it builds itself, because only the command knows where the PRD is. The skill now runs the command only in the repo of the PRD link.

**Consequences:**
- A person who starts an epic build with an unpushed spec branch no longer hits a failed merge.
- An epic over several repos merges the spec in one repo only.
- A script that reads the JSON output finds one more key.
