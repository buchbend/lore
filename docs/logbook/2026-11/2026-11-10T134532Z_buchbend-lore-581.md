**2026-11-10** · Christof Buchbender · buchbend/lore#581

**Why:** The index told an agent what a repo holds. The index did not tell the agent where else to ask. The places are the wiki, the tracker, the sinks, the sources and the other scopes of the person. An agent asked the person for a term or a fact that Lore already held.

**What we did:** The index now opens with a "Route" group and a "Scopes" group. See [#581](https://github.com/buchbend/lore/pull/581) (name the route and the scopes in the index) and [#576](https://github.com/buchbend/lore/issues/576) (the issue). Both groups come from the config of the person, not from a file of the repo, because the route is a fact of the machine. A `command` sink names its tool by a `hint` key, not only by the first word of its `run` line. A `run` line can open with shell syntax. The directive gains one line: ask Lore before the person. The limit of the directive block rises from 700 to 800 characters.

**Consequences:**
- Users: SessionStart and `lore index` name the wiki, the tracker, the sinks, the sources and each scope.
- Users with a `command` sink: the index names the tool only when the `run` line starts with it. `lore setup sink command --hint` sets the tool.
- Other repos: nobody notices.
