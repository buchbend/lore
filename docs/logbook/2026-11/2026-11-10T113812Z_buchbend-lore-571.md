**2026-11-10** · Christof Buchbender · buchbend/lore#571

**Why:** Epic [#555](https://github.com/buchbend/lore/issues/555) (index-first context and the lab notebook) shipped `lore index` and `lore lab`. Its reviews listed seven small defects that did not block the merge, filed as [#566](https://github.com/buchbend/lore/issues/566) (loose ends of the index and the lab notebook). Two of them showed at every session start: an empty question line in the index, and a read of every lab file.

**What we did:** [#571](https://github.com/buchbend/lore/pull/571) (loose ends of the index and the lab notebook) fixes all seven. The hardest was a marker of the index block that `AGENTS.md` quotes. The first fix matched code spans and code blocks with a pattern, and the review found four forms that the pattern missed. We now use the place of the marker, not a pattern: a marker counts when it opens a line outside a code fence. Every quoted form puts text before the marker, so one rule covers them.

**Consequences:**
- A person who reads the index sees the question of each lab entry, newest first.
- A session start parses three lab files at most.
- A person who quotes a marker in `AGENTS.md` can run `lore index --write`.
- `lore lab add` records a data path from the repo root.
