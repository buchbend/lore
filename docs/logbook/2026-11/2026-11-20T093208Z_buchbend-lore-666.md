**2026-11-20** · Christof Buchbender · buchbend/lore#666

**Why:** Since [PR #663](https://github.com/buchbend/lore/pull/663) (flush across worktrees and archived ledgers), `lore log flush` reads archived ledgers too. Some sinks fail for good. A person deleted the ledger line to give one up. Now the archive brings the line back ([#665](https://github.com/buchbend/lore/issues/665), give up a sink).

**What we did:** `lore log drop <key> [--sink <name>]` writes `<sink>=dropped` to the ledger of each checkout that holds the entry ([PR #666](https://github.com/buchbend/lore/pull/666)). We added a command under `lore log`, not a state on `ledger-set`. A logbook line carries no outcome, and a sink state is a logbook concept. Per sink, delivered beats dropped and dropped beats undelivered, so an old archive cannot bring a dropped sink back.

**Consequences:**
- Users: a dropped sink leaves the SessionStart banner and `lore status`, and `flush` stops retrying it.
- Nobody outside this repo notices.
