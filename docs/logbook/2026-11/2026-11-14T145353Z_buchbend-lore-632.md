**2026-11-14** · Christof Buchbender · buchbend/lore#632

**Why:** Release 0.107.0 made OpenCode a second host for Lore ([#615](https://github.com/buchbend/lore/issues/615), OpenCode as a host). A person who moves between Claude Code and OpenCode on one repo still met four defects. The mute missed the MCP tools, a nested Claude Code took the OpenCode host, old session files stayed, and five small review findings stayed open.

**What we did:** Three features fixed the defects ([#629](https://github.com/buchbend/lore/issues/629), [#627](https://github.com/buchbend/lore/issues/627) with [#626](https://github.com/buchbend/lore/issues/626), [#628](https://github.com/buchbend/lore/issues/628)). Host detection checks the Claude Code markers before `LORE_HOST`. The OpenCode plugin removes the Claude Code variables from its own environment, not a special case in host detection, so both nesting directions work. The plugin refuses `lore.` MCP tool calls of a muted session. OpenCode capture removes session files older than 7 days once the transcript index holds them.

**Consequences:**
- OpenCode users: `lore update` rewrites the plugin with the new mute and environment rules.
- Claude Code users who start `claude` from an OpenCode shell get Claude Code tier models.
- Nobody else notices.
