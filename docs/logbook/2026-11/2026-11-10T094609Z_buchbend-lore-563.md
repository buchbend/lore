**2026-11-10** · Christof Buchbender · buchbend/lore#563

**Why:** A review on 2026-11-09 found that the SessionStart banner told an agent how to behave and named little of what a repo holds. A session without the plugin saw no pointer at all. Lab work, such as a calibration run with its result, had no home.

**What we did:** `lore index` prints one short index of a repo: terms, ADR titles, current PRDs, roadmap headings and the newest lab entries. `AGENTS.md` holds a committed copy, and the banner does not repeat a current copy. The filing routing moved to `lore style show filing`, a pull, not a banner block, because an agent needs the routing only when it files. The MCP server lists seven tools, not eleven. The lab notebook writes one stamped file per experiment ([ADR 0019](https://github.com/buchbend/lore/blob/main/docs/adr/0019-the-lab-notebook.md), the lab notebook). Details: [#563](https://github.com/buchbend/lore/pull/563) (epic: index-first context and the lab notebook).

**Consequences:**
- Users: a session starts with the index. `/lore:verify` is the one way to record a verdict.
- Authors of ADRs: the template asks for four sections, not nine.
- Lab users: `lore lab add` and the `experiment` skill are new.
- Other repos: run `lore index --write` once to get the block.
