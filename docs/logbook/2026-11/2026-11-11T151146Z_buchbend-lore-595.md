**2026-11-11** · Christof Buchbender · buchbend/lore#595

**Why:** The freshness layer marked a wiki note as out of date at read time. It dates from the time when curators wrote session notes into a wiki without a review. Since [ADR 0012](https://github.com/buchbend/lore/blob/main/docs/adr/0012-agents-file-facts-as-repo-artifacts.md) (agents file facts as repo artifacts), a wiki edit is a pull request, and a stale note gets its fix there. On 2026-11-11 the layer found no marked note in the wikis `ccat` and `personal`. Each search hit cost one file read and one `git` call.

**What we did:** [PR #595](https://github.com/buchbend/lore/pull/595) (retire the freshness layer and the verdict worklist) removes the layer in full. The `freshness` key gets no deprecation period, because no note carried a marker. `lore_search` keeps the score order of the full-text backend, so the PR adds no sort code. One new test file pins the acceptance criteria of [#591](https://github.com/buchbend/lore/issues/591) (retire the freshness layer).

**Consequences:**
- Users: the SessionStart status line shows no pending-verdict chip. `/lore:verify` and `lore verdict` are gone.
- Agents and tools that read `lore_search` or `lore_read`: the replies hold no `freshness` key.
- Wiki admins: `lore wiki lint` writes no `orphan_set` key into `_catalog.json`. The lint report still names a broken wikilink.
