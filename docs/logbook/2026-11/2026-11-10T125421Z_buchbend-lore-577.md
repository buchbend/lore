**2026-11-10** · Christof Buchbender · buchbend/lore#577

**Why:** `AGENTS.md` held a generated copy of the index: the terms, the ADR titles, the current PRDs and the roadmap headings. No step kept the copy current, so each new ADR or term left the copy stale until a person ran a command. [#567](https://github.com/buchbend/lore/issues/567) (keep the AGENTS.md index block current in every harness) asked for a git hook to repair the copy. The owner chose to remove the copy.

**What we did:** [PR #577](https://github.com/buchbend/lore/pull/577) (retire the generated index block of AGENTS.md) removes the copy and the code that wrote and checked it. SessionStart now injects the full index in every session, not a pointer to the copy. The index reads its inputs at call time, so it has no stale state. [ADR 0020](https://github.com/buchbend/lore/blob/main/docs/adr/0020-session-start-delivers-the-index.md) (SessionStart delivers the index) records the reason: each fact has one home.

**Consequences:**
- Users: `lore index --write` and `lore index --check` no longer exist. Each exits with a usage error.
- Users: the SessionStart text holds the full index, also in a repo whose `AGENTS.md` still holds an old copy.
- The person who onboards a repo: the scaffold adds a short paragraph, `## Where to look`, to `AGENTS.md`.
- Other repos: a repo with an old copy keeps the copy until a person removes it by hand.

- Not yet checked: whether any repo outside `~/git` on the owner's machine holds an old copy.
