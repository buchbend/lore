**2026-10-14** · Christof Buchbender · buchbend/lore#501

**Why:** Logbook entries read as lists of issue numbers. They pointed to every home but explained nothing, so a colleague who picked up a feature could not follow the reasoning. The author could not either, a month later. Three rules caused it together: the question "who worked on what", "restate no fact that has a home", and one paragraph of 80 words.

**What we did:** An entry now has four labelled parts and up to 300 words, and `lore log add` checks the labels ([#500](https://github.com/buchbend/lore/issues/500), logbook entries explain the reasoning). An entry may summarise facts from the PR and the ADRs, not only link them. The entry is dated and nobody edits it, so the summary cannot drift ([ADR 0017](https://github.com/buchbend/lore/blob/main/docs/adr/0017-the-logbook.md), the logbook). We chose "Consequences" over "Who notices" and "Downstream effects", because the team already reads it in every ADR. The review found that a union merge of the monthly file dropped the lines two entries share. The `file` sink now writes one file per entry.

**Consequences:**
- Daily reports in project-manage show longer entries, split by label.
- An agent with the old skill text gets exit code 2 and the name of the missing label.
- New entries land in `docs/logbook/YYYY-MM/`, one file each. Old monthly files stay, and `lore log show` still prints them.
