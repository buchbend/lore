**2026-10-14** · Christof Buchbender · buchbend/lore#503

**Why:** A search test failed on any machine that holds a real search index in `~/.cache/lore/`. The continuous integration (CI) run passed ([#502](https://github.com/buchbend/lore/issues/502), isolate the search index cache in the search source tests). The cause went further: every test run read and wrote the index of the person who ran it.

**What we did:** The shared test setup fakes the home folder for each test. `fts.py` read the home folder once, at import, so the fake came too late. The module now reads the home folder each time it needs the index path ([PR #503](https://github.com/buchbend/lore/pull/503), read the home folder at call time). We fixed the cause, not the one test file the issue named. A fixture line there would have left every other test writing to the real index. Five tests had leaned on the shared index. Lore's MCP (Model Context Protocol) server skips a reindex that ran moments before, and those tests found notes that an earlier test had left. The shared test setup now resets that throttle before each test.

**Consequences:**
- Developers: the test suite no longer touches your search index. Rows that older runs wrote, for the wikis `demo` and `private`, stay in the index.
- Users: nothing changes. A running Lore process keeps one home folder.
