**2026-10-15** · Christof Buchbender · buchbend/lore#515

**Why:** No artifact answered "Where is the code heading, and in what order?". The answer lived in the owner's head or drifted into a `CLAUDE.md` ([PRD 0018](https://github.com/buchbend/lore/blob/main/docs/prd/0018-the-roadmap.md), the roadmap). Lore also used the word "roadmap" for the feature table of an epic, so the word could not carry the new meaning.

**What we did:** Epic [#510](https://github.com/buchbend/lore/issues/510) (the roadmap) adds a `ROADMAP.md` per repo and `lore roadmap add`, which files an idea under "Not placed yet" ([PR #512](https://github.com/buchbend/lore/pull/512)). The workflow skills read the roadmap, link plans to its items and remove shipped items ([PR #514](https://github.com/buchbend/lore/pull/514)). The epic table is now the build order, checked by `lore workflow validate-build-order` ([PR #513](https://github.com/buchbend/lore/pull/513)). A test now enforces ADR 0018 (Lore and project-manage meet only through generic contracts): no module under `lib/` imports a project-manage package.

**Consequences:**
- Users: reinstall the CLI with the plugins. The skills call `lore roadmap add` and `validate-build-order`.
- Developers: the Python module `lore_workflow.roadmap_validator` is now `lore_workflow.build_order_validator`, with no shim.
- Agents: a feature idea outside the task goes to the roadmap through the run's pull request. A defect still goes to an issue.

**Not done yet:**

- [#517](https://github.com/buchbend/lore/issues/517): where `handover` sends a deferred feature idea.
- [#518](https://github.com/buchbend/lore/issues/518): one merge rule for a standard epic PR in `build`.
