**2026-10-25** · Claude · buchbend/lore#531

**Why:** A repo rarely stands alone. In the `ccatobs` scope, `data-center` reads the tables of `ops-db`, and other repos call the REST API of `data-center`. No file held these edges in a form an agent reads. Teams wrote them into each repo's `AGENTS.md`, and the copies drifted ([#531](https://github.com/buchbend/lore/issues/531), the system map).

**What we did:** A system map is a wiki note at `systems/<name>.md`. Its frontmatter lists the repos and the edges: consumer, producer, interface, pin, and what breaks. The edges go in the wiki, not in each `AGENTS.md`, because ADR 0014 (one home per fact) gives each fact one home. SessionStart shows the neighbours of the current repo. `lore map` prints the edges, and `lore map scan` proposes edges from dependency files without a model. The `/lore:map` skill opens a wiki PR, and a human merges it.

**Consequences:**
- Agents in a mapped repo see their neighbours at SessionStart.
- People in a folder scope see a count of candidate edges that the map lacks.
- `orient`, `to-epic` and `build` read the pin of an edge.
